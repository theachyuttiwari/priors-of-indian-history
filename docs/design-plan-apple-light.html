What did they do before?

A redesign of Priors in the Apple manner: light, quiet, one column, and one strong element. The record is about governments and protest, so the design must not take a side. Colour carries no meaning. Shape carries the category.

The one bold element

The home page opens with the whole record on one line, 1974 to today. Each tick is a precedent, drawn from the 23 files in content/precedents/. The filled mark at the right edge is the event happening now.

Tap a tick to open that precedent. Ticks that share an action type with the current event stay dark, and the rest fade. This answers the site's question in one glance, before any text.

Type. The system font only: San Francisco on Apple devices, Segoe UI on Windows, Roboto on Android. Fraunces, Inter and JetBrains Mono go. The site gets faster, and headings read as native text. Headlines are 700 weight with tight tracking. Body text is 17px in a 65-character column. Dates use tabular figures.

Light first. Dark mode stays and follows the system setting. It uses true black, not a tinted near-black.

Shape, not colour

The five action groups in src/lib/schema.ts get a hollow glyph each. All glyphs are the same ink colour and the same size, so no group looks more alarming than another. The label always appears next to the glyph.

In power or in opposition. A text label, "In power" or "In opposition", replaces the gold and blue quote edges. Both quotes get the same grey edge.

Compare grid. One grey ramp from Surface to Ink replaces the blue ramp. It still means "more entries in the archive" and nothing more.

Build steps

  1. Replace the tokens in src/app/globals.css and remove the Google fonts from layout.tsx.
  2. Add a Glyph component and use it in ActionChip and Timeline.
  3. Build the year strip as a static SVG from getPrecedents(), so it works with no JavaScript.
  4. Change PrecedentCard into a row and update the home page and the precedents list.
  5. Change Positions, compare/page.tsx and the precedent page header.
  6. Run npm run validate and npm run build.
  7. Take screenshots at 1280px and 390px, in light and dark, and fix what they show.
  8. Commit on design/apple-light. Do not push, merge or deploy.

Decisions for you

D1No hue at all.

Default: links and the "now" mark are ink. The alternative is Apple's link blue #0066cc. Blue is close to some party colours, so I recommend no hue.

D2Light first.

Default: light is the main design, and dark mode follows the system. The current site is dark only.

D3The icon changes.

Default: the red "PO" square becomes a monochrome mark. Red reads as a party colour too.

Say "go" to accept all three defaults, or name the ones to change.
